# Dokime Document

Use when authoring or reviewing Dokime test case templates, document sections,
document cards, or plots.

## Captured Inputs And Outcomes

- `use dokime::prelude::*;` is the canonical opening of a template file: one
  glob names the seven stage grants (`InitializationContext`, `ResourceContext`,
  `TraceabilityContext`, `StepContext`, `ObserverContext`, `CleanupContext`,
  `CriterionContext`),
  the document types a template's `document()` builds with
  (`Document`, `Section`, `Plot`, `Card`, `Line`, `Band`), `TraceabilityRow` and
  `TraceabilitySection` for its `traceability()` hook, `Tick` for an observer's
  own cadence, `Slot` for a handle one step opens and a later one closes,
  `host` for the runtime's own streams and records, and the standard stream
  adapters `ctx.listen::<T>()` answers with (`Stream`, `StreamExt`,
  `Elapsed`). Keep a named import for anything the file uses outside that
  set — a foreign stream type, `DocumentTagged`, `PlotStyle`, and the like.
  Never `Error`, `Result`, `Value`, `Parameter`, a builder type, or a raw
  map: a plugin declares its own `Error` and `Result`, and a glob that
  shadowed either is the one collision that bites.
- Keep each template in its owning `snake_case` module/file, with `PascalCase` Rust types. The `cargo dokime new` starter's `src/suites/soak/hold.rs` is the worked example of one complete template; Mini's charger testbench is the embedded-application one. The route plugin under runtime test fixtures is not a product template example.
- AC input voltage is a test parameter. An image output directory belongs to a plugin settings section. A per-cycle fact — who ran it, the host, its git identity — is host traceability sampled from `host.system` itself, neither a parameter nor a setting. Use `ctx.setting::<T>("id")?` for the captured ordinary setting; do not invent per-template configuration or credential catalogs.
- Every parameter defaults to `single`: one complete value of its declared Rust type. `#[parameter(expansion = "cartesian", default = [1, 6, 11])] stream: i64` makes three cases. `#[parameter(default = vec![1, 6, 11])] streams: Vec<i64>` passes the entire list to one case. `#[parameter(expansion = "cartesian", default = vec![vec![1, 6], vec![11]])] streams: Vec<i64>` makes two cases, each receiving a complete list. A Boolean is mutually exclusive in `single` and may select both values when expanded.
- Use `expansion = zip("point")` to pair candidates by position. Every member requires equal candidate counts; no implicit broadcasting. Filtering one member filters whole paired rows. Groups combine Cartesianly with independent axes and other groups. This is separate from presentation `group_id`.
- `Vec<T>` declares a typed list, `Option<Vec<T>>` permits absence, and `min_items`/`max_items` bound each complete list. Choices and numeric bounds apply to every element. Expansion never changes the field type. `Parameter::expansion(ParameterExpansion::Cartesian)` is the runtime builder equivalent; `ParameterDefault::space` supplies candidate expressions without implicitly choosing expansion.
- A list refuses a bare scalar with a message that names the parameter, rather than wrapping it into a one-element list. The untyped `Parameter::array` still wraps; prefer a `Vec<T>` field for anything an operator edits.
- A template's parameters are one `#[dokime::parameters]` struct named on its attribute. Every stage and every criterion reads the decoded value with `ctx.parameters()`, and a plot references one by its typed handle — `SoakParameters::target_c()` — rather than by a string expression, the same way a plot references a column.
- `StepContext::secret` is a synchronous runtime-only read of a declared secret reference and returns a redacted `Secret`; expose it explicitly only where needed. `CriterionContext` reads captured settings but cannot access secrets. Static template/document declarations never read runtime settings, secrets, or environment variables.
- Admission freezes the template/documents, resolved parameters and definitions, settings/references, and provider identity/digest. Live execution and reports use that snapshot, not a later edited catalog. Ordinary serialized state never includes secret material.
- Preserve `Invalidated` as a distinct terminal status and retain results/evidence already collected. Document finalization must not overwrite these results or convert invalidation into successful completion.

## One Ordered Document

- A traceability section grows by statements like a document `Section`: `let mut dut = TraceabilitySection::new("dut", "Device Under Test");` then `dut.row(TraceabilityRow::text("serial_number", "Serial", serial));`, one row per statement, and the hook returns the sections in order. A row is one expression, with `.unit(…)` and `.source(…)` on the row value; there is no chained section builder.
- A document is one ordered list of sections. Every section is visible all the time, in the live GUI and in the report. There are no views, no view tabs and no per-view card exclusion: order is the layout.
- A section is built from its label, the way a plot is: `let mut charging = Section::new("Battery Charging");` derives the id `battery.charging`, and `charging.id("charger.charging")` overrides it only when something else addresses the section by id — a `ctx.document().note(section_id, …)`, a runtime addition aimed at it, or a test assertion. A document keeps its explicit id, because it is a real key: `Document::new("default", "Charger Qualification")`.
- The host's default document is composed, not tagged: the result built-ins first (`execution.result` — steps, criteria — then Operator Notes), then the authored sections in composition order, then the evidence built-ins — Records, Artifacts, Media, Traceability. A cycle document has Records, Artifacts and Media; it has no steps, criteria, traceability or notes of its own.
- Use document id `default` for the autoregistered runtime document. Do not introduce additional document ids unless the product has a document selector and a concrete workflow for multiple documents.
- Built-in cards are host-owned. An author may place one in a section, but never redefine its body, and a built-in section id an author reuses is replaced by the host's rather than duplicated.
- A running attempt adds to that declared skeleton rather than replacing it: every stage — `initialize`, `resources`, `traceability`, a step, `cleanup` — and a template observer reach `ctx.document()`, whose verbs add by id: `section(Section)`, `plot(section_id, Plot)`, `card(section_id, Card)`, `note(section_id, text)`. An id the declared skeleton already holds is refused into the execution log and changes nothing; nothing declared can be removed or reordered; a criterion is handed no document at all. Each accepted addition is one evidence frame, delivered live, applied after the authored sections and before the built-in sections, and persisted so the stored report and the live document are the same document.
- A long table paginates inside its own card. Nothing is hidden behind a tab.
- Keep template-specific sections, cards, plots, artifact references, and traceability in the Rust file or template-private module that owns the template. Use shared document modules only for genuinely reusable card builders or suite-wide document concepts.

## A Plot Names Its Columns Through The Row That Declared Them

- Presentation lives in a document, never on a contract. A telemetry contract declares columns, units and roles; it does not say what a plot draws. There is no `default_y`.
- A row declaration writes one typed handle per column plus the `timestamp` the host stamps, so a plot is built `let mut voltage = Plot::time_series("AC Voltage"); voltage.y(SampleRow::column_voltage_v());` and a renamed column is a compile error rather than an empty plot.
- A field's declaration reads `format = …` beside `unit = …` — `#[row(unit = "°C", format = fixed(1))]` — for how the value renders in a plot axis, a legend, or a table cell: `format::fixed(1)`, `format::scientific()`, `format::engineering()`, `format::si()` for a number, `format::clock("%H:%M:%S")` for a wall clock. There is no number pattern mini-language; the five number kinds cover an axis, a legend and a table cell.
- A handle resolves its stream through the home the row declared with `#[dokime::stream(id = …, label = …)]`. A template's own stream carries the same marker on the function that publishes it — `#[dokime::observer(interval_ms = …, streams = Streams)]` — and names neither the id nor the label again: `streams = Streams` names the stream by its row type, `<Row>::STREAM` is its declared id, and the observer calls `ctx.publish(row)` instead of returning one. For a plugin-level producer, the attribute lands on its inherent impl and declares `streams = Streams` and/or `records = Records`; its `observe` method publishes through `PluginObserverContext`. A template-local observer names a shared stream the same way, with `streams = Streams`.
- A measurement shape serving several suite-owned streams declares no home: bind its columns at the plot with `SampleRow::column_voltage_v().on(stream)`. That is the same rule `ctx.stream::<Row>().into::<Stream>()` already applies to pushing those rows.
- Host streams an author does not own stay string expressions: `telemetry("host.system", "cpu_load_percent")`.
- A data expression folds its values with one member of the Harmos aggregate vocabulary: `.count()`, `.sum()`, `.mean()`, `.median()`, `.min()`, `.max()`, `.rms()`, `.std()`, `.percentile(95)`, or `.aggregate(Aggregate::…)`. Each is `DataTransform::Aggregate(harmos::Aggregate)`, carried on the wire and in storage by its name (`mean`, `p95`), and the host answers it through `harmos::signal::Series` or the Harmos storage reduction; there is no Dokime statistic of its own. `per_case`, `time_between`, `telemetry_at_or_before` and `detail` select what is folded and are not aggregates.
- A template names no plugin. What it says about the one that will run it is `calls = CalledRoutes` on `#[dokime::template]` — the routes its stages, observers and criteria reach with `ctx.call::<Route>(request)` — beside `subscribes = Inputs`, `records = Records` and `streams = Streams`, which each select a named catalog. A card that needs a value only the bench can answer reads it through a step that called for it, not through a plugin handle: there is no `ctx.plugin()` on a template stage.
- What a plot or a telemetry card can draw is what the run captured. A template's own streams are captured because it pushes or samples them; a global stream — the host's, or another plugin's — is captured only because the template named its type in `subscribes = Inputs` on its attribute, which is what leases it for every execution and makes its rows that run's evidence. So a series that renders empty is fixed in `subscribes = Inputs`, not in the card. No cadence is stated anywhere in a document: the stream's one observer declared how often it measures.
- Plots are typed constructors on one namespace — `Plot::time_series`, `Plot::histogram`, `Plot::fft`, `Plot::sigma_interval`, `Plot::xy_scatter`, `Plot::box_summary` and the rest — each returning a plain value an author configures in place with `&mut self` methods. `plot.reference_line(label, quantity, line)` and `plot.reference_band(label, quantity, band)` name the quantity they are drawn against, so a band expressed in °C cannot land on a seconds axis; `Band` and `Line` are plain values too, bound with `let` rather than chained — `let band = Band::around(SoakParameters::target_c(), SoakParameters::band_c());` is `target ± band` as that case resolved them, named by the typed handles `#[dokime::parameters]` writes rather than by strings. `Band::parameters("target_c", "band_c")` is the same band for a host or generator that has no parameters type to name.
- A histogram bins one value and the host counts it, so the value is its x and the count is its y: `let mut ready = Plot::histogram("Time Until Ready"); ready.x(ReconnectionRow::column_time_until_ready_s());`. Its `x_format` and `unit` describe that value axis, its y axis reads "Count", and a `.y(…)` or a `y_format` on a histogram is refused. A box summary is the other way round: it draws the value vertically, so `Plot::box_summary` takes exactly one `.y(…)`.
- `plot.x_format(…)`/`plot.y_format(…)` override a column's declared format for that plot's axis. A `time_series` plot's `x_format` takes a time format — `format::elapsed_seconds()`, `format::elapsed_minutes()`, `format::clock(…)` — because it draws the row timestamp automatically; every other plot's `x_format`, and every plot's `y_format`, takes a number format. A plot that needs a number x axis instead of the automatic timestamp is `Plot::xy_line`, not `Plot::time_series`.
- Records reach a plot as handles too, from the record type rather than its id: `#[dokime::record]` writes `HoldReached::marker()` for the axis markers and one accessor per declared field — `HoldReached::reached_after_s()` — for a value a card reads off a record. Renaming a record or a field stops the plot compiling. A record this plugin does not own, a host prompt for instance, stays a string: `dokime::document::marker("prompt.request.form")`.

## Record Lifecycle

- A template states the identity of what it is testing through its `traceability` hook, as typed sections and rows with units. Never encode identity in records, notes, or `record=` log lines for a card to reassemble: those have no schema, no units, and no owner.
- The `leases` section is the host's, not the template's. It is derived on every execution that held a global stream and names each hold: the stream, the `owner` whose observer produced its rows, the window as `leased_from` and `leased_until` — reading `open` while the hold is still held — and `shared_with` when other runs were reading the same rows. A hold whose owner restarted mid-lease carries a `gap` row saying the stream went quiet, and the run continues. An author neither writes nor overrides it: `leases` is one of the names the runtime reserves for its own derived groups, and an authored section claiming one is refused at admission.
- Operator Notes are operator evidence, not template output. An operator files a Markdown note against the selected cycle or execution with `Notes/CreateNote` and revises their own with `Notes/EditNote` until that owner seals; a sealed owner refuses both with `FailedPrecondition`, and its report renders the notes it froze, read-only, with their author.
- Evidence sealing is the stable boundary. Do not infer continual report regeneration or post-seal mutation. If a change requires new generation after sealing, explain the added lifecycle and obtain explicit direction first. Inspect the current finalization owner before changing it.
- Prefer artifact-provided document sections and record listeners for record-driven product document behavior; keep the built-in runtime document generic.
- Review a template's document by running it: `dokime::plugin::testing::Harness` returns the traceability sections, the records and the artifacts the run produced, and `report.samples::<C>()` returns one stream's rows as the shape that stream declared, so what a card will render is readable from a test rather than only from the GUI. `report.document()` reads back the document exactly as the run left it — the declared skeleton plus every addition a stage's `ctx.document()` made — while `<Template as DeclaredTemplate>::declaration()` is the frozen document the template alone wrote, before any stage ran.
