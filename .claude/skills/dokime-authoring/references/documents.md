# Dokime Document

## Captured Inputs And Outcomes

Use captured parameters and evidence for criteria and documents. Preserve collected evidence and the distinct `Invalidated` terminal outcome.

Records carry discrete typed facts; streams carry typed rows. Declare records, rows and streams once and reference their types from catalogs.

## One Ordered Document

A document contains ordered sections with cards and plots. Keep template-specific document declarations with the owning template.

Initialization, traceability, steps, observers and cleanup can add document evidence. Criteria read captured evidence without document mutation.

## Typed Streams

Stream declarations own row schemas, column units and roles. Document declarations own plot presentation. Use declared typed columns for plot evidence.

## Record Lifecycle

Keep cycle, execution and provider identity with captured records. Retain records and samples independently of which document displays them.

## Report Materialization

Reports use captured execution evidence. Preserve test outcomes when report publication fails; publication failure is separate from the execution verdict.

Storage remains development v1. Incompatible schema changes require a fresh storage root, never a silent reset of existing data.
