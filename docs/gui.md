# Desktop GUI

`crates/dokime-gui/` is a Tauri 2 desktop shell with a Vite, React 19 and
Tailwind CSS v4 frontend. Paths below are relative to it. The same frontend code
serves the live operator shell and the self-contained report renderer, so
changes to shared theme or document rendering must account for both `src/app`
and `src/report`.

- `src/generated/organization/` and `crates/dokime-runtime/dist-report/report.html`
  are generated by `mise run prepare:organization` and `mise run prepare:report`;
  do not hand-edit them.
- Vitest stories are one file per production-domain workflow. Extend the story
  that owns a behavior instead of adding a file per widget.

## About And Build Versions

Settings › About shows **Desktop Version** from the native `desktop_build` command
and, while connected, **Backend Version** from the backend identity, since a remote
backend may run another build. Each reads `v0.1.2 · 766330b7 · nightly`: the short
commit, `-dirty` for uncommitted local changes or `unknown`, then the channel when
one is known. Clicking the short commit copies the full commit. Formatting lives in
`src/features/settings/sections/build-version.ts`. A browser build without the
native shell shows only the bundled frontend version.

## Desktop Launches And Storage Ownership

Every launch opens its own desktop window. Launch arguments and deep links belong
to that instance; there is no desktop lock, focus channel or forwarding to another
window. Startup resolves the distribution identifier before configuring Tauri's
application directories, logs, settings, organization pack and WebView profile;
a distribution does not create a second root under the compiled default identifier.

The local backend keeps an exclusive `local.lock` lease on its data folder.
An occupied folder fails immediately as `storage::Error::Owned`, becomes the
server's `host::Error::BackendRunning { root }`, and reaches the connection screen
as `DesktopSessionError::BackendRunning { root, message }`. The message identifies
the folder and the other instance's backend. The window retains Start Local
Backend, saved-backend connection controls and Settings: connect to another or
remote backend, or close the other instance and retry. An attached connection uses
its existing client preferences when the occupied Local backend cannot supply them.
Storage reset and backup still refuse an occupied folder with `BackendRunning`.

## Cycle Lists And Restart Recovery

The Cycles home and sidebar share `Execution.ListCycles`. The backend selects
current live cycles and durable sealed cycle headers as one list, with the same
filter, ordering and continuation rules. A live cycle supersedes its saved
checkpoint; each cycle appears once. Recent cycles remain visible after starting
another cycle or restarting the desktop. Archive selection applies to both sources.

`state.json` and `state.jsonl` under the data root recover current work. Sealed
cycles are retired from that state to keep checkpoints bounded; their durable
history remains the source for subsequent reads. Startup marks unfinished
executions Interrupted, records the restart reason, and closes admission to their
cycles before accepting new work. Interrupted cycles report Stopped. Pending
report finalization resumes from its frozen terminal header. A seal that cannot
complete settles as Seal Failed: the Cycles home lists it under Needs Attention,
and the cycle's control card shows the cause with Retry Seal and Archive, each
behind a confirmation. Startup does not retry a Seal Failed cycle.

## Keyboard Focus And Theme Colors

Keyboard focus uses the optional `--focus-ring` token, independently of `--primary`,
`--destructive` and the organization palette's required `--ring` token. Tailwind's
`ring-ring`, `border-ring` and `outline-ring` utilities all use `--focus-ring`.
Invalid controls continue to use `--destructive`.

Organization packs may set `--focus-ring` in `theme/light.css` and `theme/dark.css`;
theme families may supply `focus-ring` in their shared or mode-specific variable
maps, with the mode taking precedence. Organization materialization retains these
custom properties. Without an explicit focus color, both the desktop and report
renderer use deep blue `#00205b` in light mode and pale blue `#93c5fd` in dark mode,
even when the brand primary, palette ring and destructive colors are red.

Custom focus colors must remain visually distinct from destructive/error colors
and red brand primaries. Verify WCAG non-text contrast of at least 3:1 against the
adjacent surfaces in both modes, including the 50% opacity used by focus rings.
The defaults meet this threshold on the bundled background, card and popover
surfaces; packs that change those surfaces must verify their focus contrast.

## Units In Labels

Labels and titles show units in square brackets on the same line, for example
`Mean [Mbps]`. Use `formatUnitLabel` in `src/lib/format.ts` for table headings,
plot titles and axes, legends and stat labels. The live GUI and runtime report
HTML share this formatter. Keep structured units separate from authored labels.
Table headings truncate as a whole with the full label in a tooltip, while sort
and filter controls remain usable. Preserve the case of unit symbols.

## Document Summaries

Live document summary tiles query one saved evidence cut using bounded folds and
exact order statistics. They do not load the run's telemetry into a document input
array or reject estimated definition-size-times-row work. Plots retain their
existing independent query path. Actual output and expansion limits report the
budget, limit, amount reached and affected card.

## Telemetry Plots

Live and frozen report plots retain samples from the selected execution,
including shared streams captured by its leases. Authored stream aliases resolve
to the captured producer streams. Running reports freeze one saved evidence cut;
later samples stay outside that report. Plot previews remain bounded independently
of raw evidence retention.

An open plot settings dialog retains its edit draft while incoming payloads replace
the loading, chart or error presentation. Closing it returns focus to its plot's
settings control.

The live viewer owns the time window for all plots in its view. The options are
1 min, 2 min, 5 min, 10 min, 30 min, 1 h and All; the default is 5 min. Selection
stays with that view across rerenders. Plot definitions carry no time window.
Reports always show the full captured range, render once and omit live controls.

Refresh sits to the left of the window slider and updates every plot in the view.
Timed windows keep their automatic watch; Refresh requests fresh snapshots
immediately. All uses one finite `Plots.QuerySnapshots` request per plot on entry
and per button press, without polling, a plot watch or runtime-driven invalidation.
Each plot has its own response budget and deadline; completed plots appear while
others load, and a failed plot leaves the other plots available.
Visibility, zoom and document updates do not reload All; changed query settings
apply at the next explicit refresh. There is no background GUI plot prefetch.
The button shows progress and is disabled while refreshing. Updated hh:mm:ss
shows the last successful refresh time; failures use Notifications and leave
that time unchanged.

Live requests retain their display point budget for All (`src/plots/live-data.ts`).
Declared All plots read the write-time report checkpoints in
`crates/dokime-runtime/src/plot/preview.rs` and its `index.rs`. Their bounded exact
samples, time envelopes and occupancy grids avoid repeated full-history scans.
Checkpoints must match the plot inputs, scope and committed frontier.
Current All reads capture the checkpoint and frontier in one SQLite snapshot;
concurrent writes do not cause a raw-history fallback. Explicit historical cuts
retain their requested frontier. Exact
analyses refuse captures beyond the exact preview capacity. Markers share the
display point budget. Exact zoom statistics are unavailable after a preview has
reduced its raw samples. Timed windows retain their existing raw-query behavior.
Numeric fields and plain same-stream field expressions use
`crates/dokime-runtime/src/plot/stored.rs`; other raw projections use
`crates/dokime-runtime/src/plot/payload/spilled/`. Field expressions with values
outside the safe integer range retain the typed exact-statistics path.
Ad hoc queries without a matching
checkpoint, explicit unbounded queries and older historical frontiers still
require raw evidence reads.

Timed plot watches merge saved telemetry with the bounded, unflushed admission
tail. They follow accepted publications independently of the disk save interval,
coalescing updates with the existing 100 ms throttle rather than sending a frame
per row. The admission tail covers every unsaved row, including rows older than a
stream's declared window. A flush moves those rows into saved batches without a
gap or duplicate. Tail rows shown live can be lost in a crash. Finite queries,
All refreshes and frozen reports retain saved evidence cuts.

Numeric time series and histograms show numeric statistics. XY scatter, XY line,
XY interval, trajectory and heatmap plots omit the statistics block in both the
desktop and report renderer. XY traces keep their ordinary legend.

Event markers join the plot's legend table after the traces, one row per record
type, with a matching dashed-line glyph and the number of markers in the shown
x window. Prompt Asked and Prompt Answered have their own rows, with hollow and
filled caps matching the canvas. Marker rows leave cursor and statistics cells
empty. Clicking a row hides or restores only that kind; visibility belongs to
the plot card, like trace visibility. Frozen HTML reports retain these toggles.
Marker colors come from the theme's plot palette, and hovering a visible marker
shows its recorded label. There is no separate prompt-marker control.

Point styles draw samples independently of hover. Line, stepped and line-point
styles also mark lone samples between gaps, including nullable XY coordinates.
Window reduction retains gap separators so retained samples never gain a line
across missing evidence. Live and frozen plots share this drawing path.

Time series of declared Boolean fields, including host `host.network.internet`,
use a stepped state axis labeled **False** and **True**, without numeric statistics.
The plot projection encodes false as 0 and true as 1; missing readings are gaps.
Stored evidence retains its declared Boolean type. The live view and report use
the captured column schema to select this presentation.

## Live Artifact Files

The execution artifact tree uses mirrored `artifacts/<output>/<relative path>`
paths, including step uploads, without upload or UUID folders. Same-path uploads
reserve deterministic `.2`, `.3` suffixes before the final extension. Existing
replacement/copy-truncate `.segmentN` names remain intact.

Stream files appear when captured bytes are saved. Tree rows show Live beside
current size, then Finished or Interrupted after capture closes. The existing execution-file
follower shows growing text with its live size, then Finished after sealing,
without changing the file identity. Pausing or closing a viewer does not stop
capture. Read frames, tail offsets and retained text keep their existing budgets.
Runtime operation changes refresh the file list and size without idle polling.
Untouched baseline files do not clutter the tree; new empty files remain visible.

## Canonical Bindings And Transport

- `mise run check:typescript:generated --source` checks locally prepared bindings
  and GUI types. Without `--source`, the generated check restores staged Product
  bindings for artifact validation. `mise run check:typescript` owns formatting
  and lint.
- Rust `dokime-operations` declarations own operation contracts and
  `dokime-domain` owns their messages; do not maintain parallel domain DTOs or a second codec.
- `mise run prepare:bindings` regenerates tracked Python and TypeScript clients
  together. The `prepare:generated` prerequisite checks those tracked clients,
  builds `cargo-dokime` and the server export before report compilation,
  exports `bindings proto` and feeds its descriptors to the message generator.
  The Product frontend build runs the same generation from the Product build's `cargo-dokime`.
  The server build-script export supplies application settings
  and remains the Python generator's input; no backend process runs for generation.
  Desktop wrappers bind the ordinary methods in the canonical contract inventory;
  Harmos's additional managed `Run…` RPCs remain transport projections.
- Calls and subscriptions in `src/lib/rpc/generated/client.ts` go through the
  seam in `src/lib/rpc/transport.ts`. The desktop binds it to `ipc.ts`, the opaque
  bridge in `src-tauri/src/rpc/calls.rs`: path and protobuf bytes in, bytes or a
  typed status out, one Tauri channel per stream, fenced by the connection
  generation. The bridge never decodes or dispatches per operation; keep it so.
  Native connection handles and credentials stay outside the WebView. Listener
  status may expose this host's advertised addresses and adapter names for the
  export preview; keep that preview transient and out of logs, persisted browser
  storage and report output. Connection credentials never belong in status or profiles.
- `src-tauri/src/rpc/artifact_upload.rs` is the native file-backed adapter for
  artifact bytes. Do not add ordinary calls to it.
- Native plugin file installation returns picker, file and backend failures to
  the install dialog and an error notification. Cancelling the picker installs
  nothing; a connection change cancels its owning request.
- Tauri constructs its async response future, including command state, on the
  event-loop thread before spawning it. Native async adapters box their handler
  bodies so nested runtime futures stay off that thread's stack. Native and RPC
  command futures have a 16 KiB
  regression budget; the plugin install guard also constructs the mock-runtime future.
  Client regression guards also cover ordinary and prepared upload futures.
  [crates/dokime-client/src/transport.rs](../crates/dokime-client/src/transport.rs)
  boxes the RPC executor before composing idle and cancellation guards.
- Settings › Plugins keeps installed programs' ordinary settings editable after
  startup fails. Their declared schema comes from the verified bundle inventory.
  Secret declarations show identifiers and availability read-only; Add In Secret
  Storage opens the shared Add Secret dialog prefilled with the identifier.
  Every owner in an inactive bundle remains visible. Add missing identifiers, then
  use the page's **Retry**, which calls `Plugins.Retry` for that installation only.
- A saved settings change restarts its program. The plugin's status badge reads
  Restarting… while the new generation starts, and Restart Pending, explained as
  applying after plugin work completes, while an execution runs, pauses or stops,
  a prepared run waits, automatic continuation is between cases, or plugin streams
  still drain. Completed means a terminal execution outcome, settled plugin cleanup
  and stream drain, and durably frozen report inputs. Sealing and report publication
  after that boundary do not keep Restart Pending, even if sealing fails or stalls.
  Both states come from `PluginRuntimeSettings.restart`;
  while one holds, the page re-reads the plugin views whenever the backend's
  operations change, since the restart runs as one. A restart refused before the
  program stopped shows **Restart Refused** with **Retry** while the plugin stays
  active; a failed new generation surfaces like a failed startup. **Retry** starts
  a plugin that does not run at once, even during a cycle; retrying a running one
  shows Restart Pending until no work can reach a plugin.
- Install, reinstall, update, enable, disable and remove apply in the running
  backend; no plugin action prompts to restart the application. After a successful
  live stop, removed or replaced installations disappear with their bundles.
  A deletion failure keeps the row with its error until startup retries.
  `PluginInstallation.restart` drives the row badge (**Restarting…**, **Restart
  Pending** with its reason) and, while any row is not idle, Settings › Plugins
  re-reads the list on operation changes. A refused replacement is a
  `removal_pending` row reported as **Refused**; the previous installation stays
  **Active**. `startNotification` in `src/features/settings/plugins/plugin-queries.ts`
  raises one toast per recorded failed startup or refused restart.
  Startup notifications and plugin views keep root prose separate from collapsed
  consequence details. Set Secret opens Secret Storage’s Add Secret dialog with
  the identifier prefilled; notification history retains the same destination.
  Secret Storage References lists declaring plugins, including inactive programs.
- Completed executions and cycles retain their evidence and reports after plugin
  reload, reinstall or removal, even before sealing. Retry Seal and history reads
  use frozen report inputs, including plugin analysis results. In an open cycle,
  starting an unrun case whose plugin was removed reports that its plugin is no
  longer available; install its original revision or add a case from an available plugin.
- Toast content and history rows open the shared notification details dialog through
  native buttons (Enter/Space); the existing dialog handles Esc and focus return.
  History retains serializable failure context, including field problems, root-first
  causes, operation/request/invocation identifiers and optional backend diagnostics.
  RPC adapters decode standard Status envelopes with canonical generated domain
  error schemas. The server preserves redacted span/backtrace text in the captured
  error's optional diagnostics field when it fits the bounded RPC status details.
  Oversized technical text is omitted before the cause chain; the RPC code and
  message remain available even when details cannot fit. Technical Details is collapsed by default;
  Copy includes the complete record. Existing startup remediation actions remain
  independent of opening details.
- Desktop controls and transport errors are hand-written in `src/lib/desktop/`,
  matching their native owner modules. Change both sides together.
- `src/lib/types/` holds GUI projection contracts. API adapters map generated
  message shapes into them; preserve that boundary in components.
- Shared report components save bounded documents through
  `src/lib/api/native-document-delivery.ts`, which has no runtime RPC or generated
  message imports. File-backed artifact delivery remains in `native-delivery.ts`.
- Streams read one bounded frame at a time, require final OK status, and cancel
  with their session or subscription owner. Canceling a subscription does not stop
  the backend producer. WebView TLS requires platform-trusted certificates.

## Failure Presentation

Every GUI failure enters `failureOf(error, title)` in
`src/lib/notification-details.ts`. Its serializable `NotificationFailure` carries
a title, root message, root-first causes, field problems, operation/request/invocation
identifiers, the backend's redacted diagnostics and available client `Error.stack`.
Canonical native/RPC adapters decode backend contracts; presentation leaves retain
the stem record unchanged. Do not extract an error message in a component or add
another failure formatter.

`src/lib/failure-routing.ts` owns the routing rule:

| Failure Origin | Destinations |
|---|---|
| A view cannot load its data | ErrorCard and console |
| A user action fails | Toast, notification history and console |
| Startup, plugin or stream background work fails | Notification history, toast and console |

ErrorCard uses the destructive border and icon, independently of focus colors. It
shows the record title/message, optional Try Again, collapsed Technical Details
and Copy of the complete record. Loading and empty states retain ordinary notices.
Toast/history details expose the same technical record and client stack. Existing
remediation controls remain independent of opening details.

`reportFailure(failure, context)` emits a collapsed console group containing the
complete record through `console.error`. Console and notification delivery deduplicate
by failure identity across rerenders and repeated leaves. Keep the originating Error
or normalized record through state updates; a new failed retry creates a new
occurrence. Replayed backend outcomes use an explicit event key. History-storage
failures report to console and the history view without recursively writing history.

## Console Traces

The desktop logger and its owned backend share one bounded trace journal,
independent of the terminal log filter. Console replays retained events for the
selected Instance, Cycle or Execution scope and minimum level, then follows new
events. These process-local traces are separate from saved execution evidence;
restarting the desktop or standalone server process starts a new journal. Reconnects resume the scope cursor,
replaying retained history if its epoch or cursor expires. Stream failures show
the backend or transport cause beside the reconnect status.

## Remote Access Files

The owned local backend's Remote Access section checks inbound Windows Firewall
policy for a running non-loopback listener. **Allow In Firewall…** is the only
action that requests elevation; its rule uses the applied organization label and
allows the installed executable's TCP listener port on the served adapters'
active profiles, including a Public unidentified cable network, restricted to
local-subnet peers. Specific binds select only their adapter's profile and local
address; wildcard binds select active adapters in the listener's address family.
The notice names the affected adapters, networks and categories. Outbound remote sessions
have no firewall action. Disabling remote access attempts owned-rule removal
without prompting and reports skipped cleanup. Installers never manage rules.

Settings → Remote Access exports `.dokime-remote` through the native save adapter
in `src-tauri/src/app/desktop.rs`. Confirmation combines listener enablement and
the secret warning when stopped; running listeners export directly. Labels and
all candidate endpoints come from native owners. `RemoteListenerStatus.endpoints`
provides the same ordered addresses used by exports, with adapter names, for the
pre-export list. Physical IPv4 link-local follows routable addresses; IPv6
link-local remains excluded because remote origins have no zone-ID support.
Paired Clients permits rename.
The file bytes and raw key stay native; the export action returns only a saved path.

Picker imports and window drops share `src-tauri/src/connection/registry.rs`:
validate, save the profile/keyring association, then connect. Native import events
refresh the frontend session generation so the opaque bridge follows the new
backend. The Rust client races candidates only after TLS and identity verification;
profiles remember the winning endpoint without changing their keyring association.
