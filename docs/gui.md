# Desktop GUI

`crates/dokime-gui/` is a Tauri 2 desktop shell with a Vite, React 19 and
Tailwind CSS v4 frontend. Paths below are relative to it. The same frontend code
serves the live operator shell and the self-contained report renderer, so
changes to shared theme or document rendering must account for both `src/app`
and `src/report`.

- `src/generated/organization/` is generated by `tools/python/src/dokime_tools/build/organization.py`.
  The standalone report renderer is generated into `dist-report/` through
  `mise -C crates/dokime-gui run generate:report`; the host owns its served report bytes.
  Do not hand-edit generated assets.
- Vitest stories are one file per production-domain workflow. Extend the story
  that owns a behavior instead of adding a file per widget.

## Host Connection

The desktop has one native SDK connection owner. The WebView sends generation-fenced
commands and receives bounded Tauri channel frames; it never opens a host socket.
`src-tauri/src/connection/host.rs` owns embedded startup, readiness through
`Status.Get`, pinned remote pairing, cancellation and joined Watch/host shutdown.
`native_session/owner.rs` selects that connection and `rpc/` dispatches canonical
protobuf bytes through it. An attached host is never shut down by the desktop.

`src/lib/host/` owns canonical frontend projections. The running shell uses its
host identity, catalog, scoped client/application preferences and appearance
projections, together with secret catalog and transfer. Planning, execution detail/control,
runtime/progress Watch, prompt and live-record adapters also use canonical host messages. Case
registration uses one cycle-scoped `RegisterSelection` request; execution status
projects durable state, attributed outcome and optional live controls separately.
Run buttons use the host capabilities, including the absence of controls on imports.
Telemetry plots, incremental document frames and content read/follow/upload adapters
also consume canonical messages. The connection reads the product process epoch
from its client and validates readiness against that execution epoch; library status history is a separate resource identity. Listener values in the
preferences view come from Access; application preference saves never write that
separately revisioned resource. Missing host logo content is reported independently
of native installer appearance. Native plugin installation, pairing export, firewall
registration and verified artifact/report delivery also use the SDK connection.
The provider owns connect/read/watch/mutation timeouts; a call may explicitly
override its deadline. Replacing a generation cancels and joins its watches.
Reloading the WebView adopts and verifies the native owner's current connection,
including an imported remote profile, before considering launch arguments.
Execution progress uses `dokime.v1.executions.Progress/Watch` with its named
resource, opaque revision, pinned position and terminal flag. Its adapter projects
the served label and counts; elapsed time, ETA and a step identifier stay absent
because this contract does not supply them. The operation grammar table in
`docs/execution-host.md` distinguishes subsequent locked renames from landed routes.

The running checkpoint/history, plugin inventory/settings and diagnostics adapters
use canonical host messages. SDK and binary adapter stories prove their boundaries;
full WebView journey proof remains open. Native method availability comes from the
SDK operation catalog. Access/Status advertise their RPC bindings; the host's product
catalog currently omits those bindings, so storage source changes remain disabled
with a visible reason and a Host Request.
Desktop system startup uses `dokime-next server --endpoint ... --storage ...`
  and admits the prepared Rust SDK fixture with `plugin add`. The WebView RPC
helper uses canonical host schemas and the descriptor fence, including numeric
enums and fully qualified library service paths. System drivers now use the SDK
thermal fixture, registered cases, execution state/outcome, Access resources and
verified native delivery. Their complete WebView proof remains open.
The thermal fixture does not publish a report automatically. Stories explicitly
publish a selected evidence document before requiring a sealed download; a render
without publication correctly retains the host's Current origin.

The execution WebView currently reaches a real passed result and captured evidence,
but its document card reports Evidence Unavailable: the host sends EvidenceCut before
StructureComplete and declares cards afterward. The adapter retains its ordering,
identity and completion checks; this mismatch is a Host Request, not a disabled
execution control. The old facade inventory test is removed because that generated
facade no longer exists; type checking, the host import smoke and native IPC stories
cover the current client boundary.

Native stories retain their disposable roots outside the test runtime. After
owned tasks stop, including on assertion failure, the host fixture removes each
root's credentials through `--remove-credentials` before temporary files are
deleted. WebView and benchmark cleanup uses the same host operation. A cleanup
failure preserves the root and fails the story. Tests Build enables `testing`;
focused native desktop commands must also pass `--features testing`.

## About and Build Versions

Settings > About reads **Desktop Version** through `desktop_build` and
**Backend Version** from the connected host's `Status.Get` identity. A remote
host may run another version. The native desktop build includes its source
revision and channel when known; the current host identity supplies application
name and version without product source revision, channel or artifact target.
Those absent facts remain absent. Plugin release lookup explains why it cannot
select a host bundle until the host supplies its target.

## Desktop Launches and Storage Ownership

Every launch opens its own desktop window. Launch arguments and deep links belong
to that instance; there is no desktop lock, focus channel or forwarding to another
window. Startup resolves the distribution identifier before configuring Tauri's
application directories, logs, settings and WebView profile;
a distribution does not create a second root under the compiled default identifier.

The local host keeps an exclusive `local.lock` lease on its storage folder.
`dokime_runtime_next::Error::OccupiedRoot` reaches the connection screen as
`DesktopSessionError::BackendRunning { root, message }`. Close the other owner
before retrying, or attach to its host. An attached connection keeps its client
preferences when an occupied local root cannot supply them.

An incompatible root is refused and preserved. **Back Up and Reset** is disabled
with a visible reason: the host does not yet expose recovery that preserves its
plugins, settings, identity and secret catalog. Native recovery commands refuse
before stopping the host or touching files. Preserve the existing folder and
choose a fresh application root explicitly; the desktop never resets it silently.

## Cycles and Saved Executions

The host owns planning, execution lifecycle, frozen origins and durable evidence.
Its canonical client separates execution state, attributed outcome and live
controls; a closed or sealed execution is not itself a pass or failure.
Materialized cases retain their authored suite/template origin. The desktop SDK
story runs the shared thermal suite through its watched operator prompt,
completion, captured records, telemetry and a verified report download.

Control, Cycles and History consume the canonical projection through the shared
adapter layer. Their WebView journeys remain open because the system driver still
uses the retired CLI/fixture setup; native host proof does not establish the
screens' behavior. Storage and restart recovery belong to the host's v1 store,
not to a desktop checkpoint file.

## Organization Pack Loading

The desktop reads the installer-packaged organization folder beside the executable,
or embedded defaults when it is absent. Manifests, logos, CSS and fonts load directly
from memory, including inlined CSS URLs; loading does not use `TMP` or `TEMP`.
The native title and icon and HTML head use this appearance before the first frame.
Reports produce their initial head from the captured appearance.
There is no runtime pack import, promotion or overlay. Old active and pending pack
folders in the application data root are ignored and preserved.

## Default Appearance

The bundled pack uses carbon ink on paper in light mode and paper ink on carbon
in dark mode, with plate surfaces for secondary controls. Primary actions invert
ink and ground; links use the readable terracotta token. Cards are transparent
ruled surfaces. Shared primitives own control geometry and read the density
variables for desktop and touch sizes; status, trace, reference and focus colors
retain their independent roles.

Roboto carries working UI and card, dialog and sheet headings. Roboto Slab is
reserved for display headings and the wordmark; Roboto Mono carries technical
values. The offline Latin variable faces in `organization/fonts/` come from the
pinned `@fontsource-variable/roboto`, `roboto-slab` and `roboto-mono` production
packages in the GUI's pnpm lock. Their license texts accompany the bundled files;
the production dependency notice collector includes them in packaged notices.

## Keyboard Focus and Theme Colors

Keyboard focus uses the optional `--focus-ring` token, independently of `--primary`,
`--destructive` and the organization palette's required `--ring` token. Tailwind's
`ring-ring`, `border-ring` and `outline-ring` utilities all use `--focus-ring`.
Invalid controls continue to use `--destructive`.

Organization packs may set `--focus-ring` in `theme/light.css` and `theme/dark.css`;
theme families may supply `focus-ring` in their shared or mode-specific variable
maps, with the mode taking precedence. Organization materialization retains these
custom properties. Without an explicit focus color, both the desktop and report
renderer use deep blue `#001b4a` in light mode and pale blue `#93c5fd` in dark mode,
even when the brand primary, palette ring and destructive colors are red.

Custom focus colors must remain visually distinct from destructive/error colors
and red brand primaries. Verify WCAG non-text contrast of at least 3:1 against the
adjacent surfaces in both modes, including the 50% opacity used by focus rings.
The defaults meet this threshold on the bundled background, card and popover
surfaces; packs that change those surfaces must verify their focus contrast.

## Units in Labels

Labels and titles show units in square brackets on the same line, for example
`Mean [Mbps]`. Use `formatUnitLabel` in `src/lib/format.ts` for table headings,
plot titles and axes, legends and stat labels. The live GUI and runtime report
HTML share this formatter. Keep structured units separate from authored labels.
Table headings truncate as a whole with the full label in a tooltip, while sort
and filter controls remain usable. Preserve the case of unit symbols.

## Document Summaries

Author documents with `Document::new("Hold at Temperature")`; identifiers derive
from labels, as for traceability and sections. Use `document.id("hold");` to retain
a key across label edits. Invalid or empty derived keys and collisions in one
registry are refused with an instruction to set `.id(...)`. GUI routes continue
to select the runtime's internal `default` execution document, which merges the
template's authored content with built-in results and evidence.

Document structure commits before the saved-evidence wait. Each pending binding
uses an independent query through the existing document capture operation, with
its own cancellation and retry lifetime. Runtime invalidation preserves in-flight
card reads, so fast cards keep refreshing while an exact median is still loading.
A completed card remains visible when another card or transfer fails. Failed
bindings render the existing ErrorCard with their native diagnostic and budget
fields. Repeated sections keep a loading identity until their expansion arrives.

Repeated sections use distinct-value index pages. Previous Page and Next Page
replace the visible page at the same saved cut, including its captured definition
and scalar context. Latest resumes live refresh. Card query identities remain
stable across page and evidence frontier changes; each repeated card requests the
page that declared it. A page retains only its actual expanded output.

Live document summary tiles query one saved evidence cut using bounded folds and
exact order statistics. They do not load the run's telemetry into a document input
array. Count, min, max, mean and RMS reuse typed ingest checkpoints; a cut inside
a saved batch reads only its bounded remainder. Median remains exact and loads in
an independently loading card. They do not
reject estimated definition-size-times-row work. Plots retain their
existing independent query path. Actual output and expansion limits report the
budget, limit, amount reached and affected card.

Saved HTML uses the same card query evaluator at its frozen evidence cut.
It includes all repeated-section pages and complete authored tables, rather than
only the page currently displayed in the GUI. A failed data binding retains its
card diagnostic in the saved document.

## Telemetry Plots

`unit` is only a label. A plot's optional `scale` multiplies returned time-series
y values for display, including points, axis ticks, cursor/tooltips, statistics
and y reference lines/bands. Count and timestamps stay unchanged. Live plots and
frozen HTML use `src/plots/grouping.ts` for the same conversion, without mutating
query payloads. Explicit conversion uses a numeric axis, including encoded 0/1
Boolean values; ordinary Boolean plots retain False/True labels.
Scale defaults to 1.0 and is omitted from documents when absent. Validation
requires a positive finite constant and refuses other plot kinds, custom analyses
and alternate x axes. Filters and section repeats still use stored units;
evidence, exports, criteria, query plans and expressions remain unchanged.

Reference bands and lines belong to the plot and always use its Y axis. Bounds,
centers, tolerances and line values accept `f64` or an existing expression handle
(or `DataExpression`); constants do not become data expressions, so
`plot.y(10.0)` is still invalid. All reference values use stored units and scale
with the data when `plot.scale(...)` is set:

```rust
plot.reference_band("Requirement", -10.0, 10.0);
plot.reference_band("Limits", Parameters::lower_limit_c(), Parameters::upper_limit_c());
plot.reference_tolerance("Requirement", 0.0, Parameters::angle_tolerance_arcsec());
plot.reference_tolerance("Target ± Band", Parameters::target_c(), Parameters::band_c());
plot.reference_line("Limit", Parameters::limit_c());
```

Each case resolves its captured parameter values through the same presentation
path in live plots and frozen HTML. Missing or invalid dynamic bounds are undrawn.
In Cartesian plots, every band whose bounds resolve is drawn as a translucent fill with solid edges,
and the Y range widens to include each band and line value plus 15% padding of
the spanned values, so a band that contains every sample still shows both
edges inside the plot.

A reference keeps an explicit author color. One left at the definition default
takes the reference palette in order: a plot's bands first, then its lines. The
reference palette is a muted sequence (`--plot-reference-1` to `-4` in
`crates/dokime-gui/src/styles.css`), lower in chroma than any series color, so
a plot's first band never reads as its first trace:

| ----- | --------- | --------- | --------- | --------- |
| Light | `#415166` | `#9c8378` | `#435f52` | `#8f889f` |
| Dark  | `#8ba2b2` | `#e5d5c3` | `#987f7f` | `#dacbde` |
Document validation refuses reversed literal bounds and negative literal tolerance,
naming the plot. The development document/storage format stays at v1; existing
incompatible documents require an explicit fresh storage root, preserving old data.


Live and frozen report plots retain samples from the selected execution,
including shared streams captured by its leases. Authored stream aliases resolve
to the captured producer streams. Running reports freeze one saved evidence cut;
later samples stay outside that report. Plot previews remain bounded independently
of raw evidence retention.

An open plot settings dialog retains its edit draft while incoming payloads replace
the loading, chart or error presentation. Closing it returns focus to its plot's
settings control.

The live viewer owns the time window for all plots in its view. The options are
1 min, 2 min, 5 min, 10 min, 30 min, 1 h and All; the default is 5 min. Selection
stays with that view across rerenders. Plot definitions carry no time window.
Reports always show the full captured range, render once and omit live controls.

Refresh sits to the left of the window slider and updates every plot in the view.
Timed windows keep their automatic watch; Refresh requests fresh snapshots
immediately. All uses one finite `Plots.QuerySnapshots` request per plot on entry
and per button press, without polling, a plot watch or runtime-driven invalidation.
Each plot has its own response budget and deadline; completed plots appear while
others load, and a failed plot leaves the other plots available.
Zoom and panel-width changes request fresh detail for All. Visibility and
document updates do not reload it; other changed query settings apply at the
next explicit refresh. There is no background GUI plot prefetch.
The button shows progress and is disabled while refreshing. Updated hh:mm:ss
shows the last successful refresh time; failures use Notifications and leave
that time unchanged.

Live requests retain their display point budget for All (`src/plots/live-data.ts`).
Declared All plots read the write-time report checkpoints in
`crates/dokime-storage/src/plots/`. Their bounded exact
samples, time envelopes and occupancy grids avoid repeated full-history scans.
Checkpoints must match the plot inputs, scope and committed frontier.
Current All reads capture the checkpoint and frontier in one SQLite snapshot;
concurrent writes do not cause a raw-history fallback. Explicit historical cuts
retain their requested frontier. Exact
analyses refuse captures beyond the exact preview capacity. Markers share the
display point budget. A zoom requests its viewport from evidence even when the
whole-history preview reduced its raw samples. Plain numeric time windows reuse indexed stored buckets with first, last,
minimum, maximum and running moments. Only uncovered intervals and the admission
tail read raw evidence. The interface sends its held viewport and measured panel width;
time buckets follow elapsed time rather than sample counts. Zoom requests can
retrieve finer raw detail than the stored bucket interval.
Numeric fields and plain same-stream field expressions use
`crates/dokime-storage/src/plots/`; other raw projections use
`crates/dokime-storage/src/plots/`. Field expressions with values
outside the safe integer range retain the typed exact-statistics path.
Ad hoc queries without a matching
checkpoint, explicit unbounded queries and older historical frontiers still
require raw evidence reads.

Timed plot watches merge saved telemetry with the bounded, unflushed admission
tail. They follow accepted publications independently of the disk save interval,
coalescing updates with the existing 100 ms throttle rather than sending a frame
per row. The admission tail covers every unsaved row, including rows older than a
stream's declared window. A flush moves those rows into saved batches without a
gap or duplicate. Tail rows shown live can be lost in a crash. Finite queries,
All refreshes and frozen reports retain saved evidence cuts.

A document watch evaluates its dirty plots together at one captured cut, reusing
query deduplication and bounded storage readers. One watch message carries the
complete dirty set in request order, including each plot's snapshot, changed time buckets or error. A late sample
replaces the bucket containing its timestamp. Exact statistics arrive on their
own coalesced read and never block a redraw; their evidence revision can lag the
latest drawn frame.
The wire carries one columnar frame and series metadata. Aligned plots share
one time column; independent axes retain their own x columns. The point-series
copy is gone. The interface replaces changed buckets in its retained frame,
expires rows outside the window and applies statistics independently without
replacing the drawn columns. Reconnecting starts from a fresh snapshot.
Opening snapshots use the same grouped delivery. The plots share the revision's
transport budget; oversized payloads reduce from the retained query result,
without rereading evidence. Finite All requests keep their independent budgets.
Already delivered revisions are suppressed; keepalives remain payload-free
pending notices. The frontend decodes each revision in full and applies its
updates through one shared animation-frame commit, so the document's charts
receive the complete revision together.

Numeric time series and histograms show numeric statistics. XY (including its interval option), trajectory, contour and grid charts omit the statistics block in both the
desktop and report renderer. XY traces keep their ordinary legend.

The ten-kind catalog and input/options contract are in
[Plot Contracts](query-api.md#plots-and-documents). Contour cells and d3 filled bands
with isolines use the backend grid and validity mask; empty bins stay gaps and
zero values stay visible. Grid charts render only declared row/column entries,
groups, labels, reducer output and highlights.

Trajectory and grid charts share the plot playback primitive in
`crates/dokime-gui/src/plots/playback.tsx`: one shared Slider and Button controls
below each plot. Selection, Play, Pause and Replay use retained instants locally,
without querying or publishing another plot's window/cursor. Play stops at the
loaded end; Latest releases a held selection. New data does not move a held
selection. Empty or single-instant plots disable animation. The frozen HTML report
embeds this implementation and remains usable with networking disabled.

Plot legend tables list traces only. Clicking a trace row hides or restores that
trace within its plot card. Event and prompt markers always remain drawn on the
canvas, with no legend rows or visibility controls. Marker colors come from the
reference palette by marker kind, never from the series palette, and hovering a marker shows its recorded label through the
same tooltip for events and prompts; markers
never draw permanent canvas labels. The tooltip stays inside the plot card,
and prompt labels take precedence over event labels at the same position. It
wraps long labels and ellipsizes after three lines while retaining the start.
Live plots and frozen HTML reports share this behavior. There is no separate
prompt-marker control.

Point styles draw samples independently of hover. Line, stepped and line-point
styles also mark lone samples between gaps, including nullable XY coordinates.
Window reduction retains gap separators so retained samples never gain a line
across missing evidence. Live and frozen plots share this drawing path.
Each series takes one color, its declared color or the plot palette at its

starts at the first palette entry: the plot's title and position never offset it. Point and
line-point marks are opaque discs in that color with a 1 px plot-background
outline to separate overlapping samples. Point marks are normally 8 px, or 5 px
for dense captures; hover marks grow by 2 px.
The desktop selects its plot palette from the resolved application theme;
frozen reports use the palette applied for their displayed color mode.

## Live Artifact Files

The execution artifact tree uses mirrored `artifacts/<output>/<relative path>`
paths, including step uploads, without upload or UUID folders. Same-path uploads
reserve deterministic `.2`, `.3` suffixes before the final extension. Existing
replacement/copy-truncate `.segmentN` names remain intact.

Stream files appear when captured bytes are saved. Tree rows show Live beside
current size, then Finished or Interrupted after capture closes. The existing execution-file
follower shows growing text with its live size, then Finished after sealing,
without changing the file identity. Pausing or closing a viewer does not stop
capture. Read frames, tail offsets and retained text keep their existing budgets.
Runtime operation changes refresh the file list and size without idle polling.
Untouched baseline files do not clutter the tree; new empty files remain visible.

## Media Capture and Live Artifacts

Screenshot, Photo and Record Audio save execution uploads under `media/`,
preserving their relative names and the existing `.2`, `.3` collision suffixes.
The Media card and artifact tree refresh after a capture is saved, while the
execution is still running; runtime file updates also refresh the same inventory.
Other uploads retain their `artifacts/` paths. Captured bytes are readable before
execution completion.

Desktop previews use the generation-owned native media cache. The scheme handler
decodes Tauri's encoded cache path before validating its generation and key.
Preview preparation uses closed files and refreshes when their saved state changes.
Images are decoded on a blocking native worker with dimension and allocation
limits, then reduced to at most 960 × 960 pixels before the WebView reads them.
Audio and video expose playback controls with bounded native range reads.
Names ellipsize, retain their full text as a tooltip, and occupy a separate row
from Inspect. Frozen HTML retains its original media and download links under
`outputs/media/`, independently of the desktop preview cache.

  `dokime-protocol` owns their messages; do not maintain parallel domain DTOs or a second codec.
- `mise run prepare:bindings` regenerates tracked Python and TypeScript clients
  together. The `prepare:generated` prerequisite checks those tracked clients,
  generates frontend protobuf modules from the checked-in product descriptor. Native
  preference/default export and full generated client drift checks return with
  the desktop host switch, under the combined restoration task.
  The server build-script export supplies application settings
  and remains the Python generator's input; no backend process runs for generation.
  Desktop wrappers bind the ordinary methods in the canonical contract inventory;
  Harmos's additional managed `Run…` RPCs remain transport projections.
- Calls and subscriptions in `src/lib/rpc/generated/client.ts` go through the

  Native connection handles and credentials stay outside the WebView. Listener

  Client regression guards also cover ordinary and prepared upload futures.

## Failure Presentation

User-facing errors name the action that can resolve the failure. Offer Try Again
only when retry can help. A real unrecoverable failure directs the operator to
Settings → Diagnostics → Support Bundle so logs can reach the plugin developer.
Ambiguous stored stream definitions instead explain that the evidence cannot be
repaired and advise a fresh storage root, preserving the original files.
Failed report finalization settles Control and the sidebar through the same
terminal projection as successful publication; its durable cause remains visible
after reload. Initialization precedes ordinary steps and cleanup in both views.

Every GUI failure enters `failureOf(error, title)` in
`src/lib/notification-details.ts`. Its serializable `NotificationFailure` carries
a title, root message, root-first causes, field problems, operation/request/invocation
identifiers, the backend's redacted diagnostics and available client `Error.stack`.
Canonical native/RPC adapters decode backend contracts; presentation leaves retain
the stem record unchanged. Do not extract an error message in a component or add
another failure formatter.

`src/lib/failure-routing.ts` owns the routing rule:

| Failure Origin | Destinations |
|---|---|
| A view cannot load its data | ErrorCard and console |
| A user action fails | Toast, notification history and console |
| Startup, plugin or stream background work fails | Notification history, toast and console |

ErrorCard uses the destructive border and icon, independently of focus colors. It
shows the record title/message, optional Try Again, collapsed Technical Details
and Copy of the complete record. Loading and empty states retain ordinary notices.
Toast/history details expose the same technical record and client stack. Existing
remediation controls remain independent of opening details.

`reportFailure(failure, context)` emits a collapsed console group containing the
complete record through `console.error`. Console and notification delivery deduplicate
by failure identity across rerenders and repeated leaves. Keep the originating Error
or normalized record through state updates; a new failed retry creates a new
occurrence. Replayed backend outcomes use an explicit event key. History-storage
failures report to console and the history view without recursively writing history.

## Console Traces

The desktop logger and its owned backend share one bounded trace journal,
independent of the terminal log filter. Console replays retained events for the
selected Instance, Cycle or Execution scope and minimum level, then follows new
events. These process-local traces are separate from saved execution evidence;
restarting the desktop or standalone server process starts a new journal. Reconnects resume the scope cursor,
replaying retained history if its epoch or cursor expires. Stream failures show
the backend or transport cause beside the reconnect status.

## Remote Access Files

The owned local backend's Remote Access section checks inbound Windows Firewall
policy for a running non-loopback listener. **Allow In Firewall…** is the only
action that requests elevation; its rule uses the applied organization label and
allows the installed executable's TCP listener port on the served adapters'
active profiles, including a Public unidentified cable network, restricted to
local-subnet peers. Specific binds select only their adapter's profile and local
address; wildcard binds select active adapters in the listener's address family.
The notice names the affected adapters, networks and categories. Outbound remote sessions
have no firewall action. Disabling remote access attempts owned-rule removal
without prompting and reports skipped cleanup. Installers never manage rules.

Settings → Remote Access exports `.pair` through the native save adapter
in `src-tauri/src/app/desktop.rs`. Confirmation combines listener enablement and
the secret warning when stopped; running listeners export directly. Labels and
all candidate endpoints come from native owners. `RemoteListenerStatus.endpoints`
provides the same ordered addresses used by exports, with adapter names, for the
pre-export list. Physical IPv4 link-local follows routable addresses; IPv6
link-local remains excluded because remote origins have no zone-ID support.
The file bytes and raw key stay native; the export action returns only a saved path.

Picker imports and window drops share `src-tauri/src/connection/registry.rs`:
validate, copy the complete pairing into the pairing-file folder, then connect.
Native import events refresh the frontend session generation so the opaque bridge
follows the new backend. The Rust client tries candidates in order after TLS and
expected-backend verification. There is no credential-store association or saved
winning endpoint.
