# Remote CLI Workflows

These scripts use an installed Dokime CLI to control the maintained simulated
OBC plugin on another computer. The host must have admitted the matching OBC
plugin after a full restart. Device control, test execution and confirmation
are separate workflows; the default test asks no questions.

The matching first-party release combination is not available yet. These
examples require the Remote Streamline CLI and plugin contracts; an older
release or the unrelated PyPI package named `dokime` does not supply them.

## Connection

Keep the host's downloaded public certificate and access key on the remote
computer. Use the hostname or IP included in that certificate. Certificate
verification stays enabled; never copy the server's private key.

Copy [`../.env.example`](../.env.example) to `../.env` and replace its placeholder
with the one-time key generated by the host. The ignored `.env` file stays
private. The commands below select it explicitly; neither the scripts nor the
client search parent directories. A process `DOKIME_KEY` takes precedence over
this file. Use `--key-file ../remote.key` instead for the downloaded UTF-8 key;
an explicit key file takes precedence over both.

Every argument passed to a script is forwarded as a Dokime connection flag.
The examples below use `https://lab-host.example:8765` as an address to replace
with your host's actual endpoint, and `../server.pem` as the location where you
saved its public certificate. Saved profiles also work with `--backend lab`.

## Control The Device

```sh
sh ./control-device.sh --endpoint https://lab-host.example:8765 \
  --ca ../server.pem --env-file ../.env
```

The script lists operations, reads the manual demonstration device, powers it
on, reads it again, powers it off and performs a final read. The powered device
reports 230 V RMS; the off state reports zero. This device is independent of
the charger models owned by individual executions. Manual interventions are
not recorded as execution evidence.

Optionally save each complete response through the CLI's atomic JSON output:

```sh
DOKIME_RESPONSE_DIRECTORY=device-responses sh ./control-device.sh \
  --endpoint https://lab-host.example:8765 --ca ../server.pem --env-file ../.env
```

The directory receives `before.json`, `power-on.json`, `running.json`,
`power-off.json` and `after.json`. Each contains the CLI's ordered response-event
array, ending in a completion event. A pre-existing destination refuses the
workflow before any device operation; choose an empty response directory.
Ctrl+C stops waiting. A dispatched device command may already have acted:
read its current state before manually resending. Commands are never retried.

## Run Two Executions

```sh
DOKIME_OUTPUT_DIRECTORY=test-evidence sh ./control-test.sh \
  --endpoint https://lab-host.example:8765 --ca ../server.pem --env-file ../.env
```

The script creates a new cycle and prints its UUID. It appends one
`obc.checks.pulse` execution, prints its UUID and retained request key, explicitly
runs it, waits for its durable result and downloads `execution-1.zip`. It then
does the same for a second execution in that cycle. Completing an execution
leaves the cycle Active; only the final explicit seal closes it. `cycle.zip`
contains both members and their collected evidence.

The exit status is nonzero for a failed, blocked or cancelled result, even when
its evidence downloads successfully. Output files are never overwritten.

## Answer One Confirmation

```sh
DOKIME_OUTPUT_DIRECTORY=prompt-evidence sh ./control-prompt.sh \
  --endpoint https://lab-host.example:8765 --ca ../server.pem --env-file ../.env
```

This workflow creates its own cycle and appends the pulse with
`require_confirmation=true`. It starts that execution, discovers and displays
its pending confirmation, then answers `yes` using both the execution and
prompt UUIDs. It waits, saves `execution.zip`, seals its cycle and saves
`cycle.zip`. Pulse sampling starts only after confirmation.

## Interruption And Recovery

The POSIX test and prompt scripts catch Ctrl+C and request a stop for their
retained execution. They wait for its durable result, download
`interrupted-execution.zip`, seal their newly created cycle and download
`interrupted-cycle.zip`. They return nonzero. Sealing also cancels any unrun
members of that cycle; reserve a demonstration cycle for its script.

A connection failure cannot prove cancellation or a successful answer. Keep
the printed cycle UUID, execution UUID, request key and prompt UUID. Reconnect
to the same host and inspect that execution or prompt before manually
resubmitting. Do not create another cycle to discover whether an uncertain
request ran. A failed or interrupted export can be downloaded again from the
beginning without rerunning device operations. Existing files remain intact.

The bundles contain `manifest.json`, `evidence.sqlite`, captured `files/` and
saved `reports/`. Download before shutting down the host; later retrieval
requires restarting or reconnecting to its server.

For an institute plugin, keep this lifecycle and replace the operation IDs,
template and parameters with its discovered contracts. Do not assume its
device has the OBC demonstration's voltage or fault behavior.
